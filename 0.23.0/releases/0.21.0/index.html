    RDK HALIF AIDL 0.21.0 Release Notes

    Release date: TBD

    Base comparison: 0.20.0...0.21.0

    Headline

    The 0.21.0 cohort completes the per-module restructure — every module now owns its own state machine, build wiring, and snapshot lifecycle. Audiomixer, audiodecoder, audiosink, avbuffer, avclock, common, firmwareupdate, sensor, videodecoder, videosink all advance to 0.2.0.0 as part of the cohort-locked baseline. Audiomixer additionally jumps to 0.3.0.0 to ship MS12 v2.6 DAP runtime control plus a cross-module rename of registerListener/unregisterListener → registerEventListener/unregisterEventListener with boolean returns. The boot component completes its rename to bootreason. The release-management toolchain (release.sh, snapshot creation, mkdocs versioned nav, branch + tag automation, AIDL hash gate, verification builds) lands in production form. linux_binder_idl moves to 2.3.0 to pick up the Yocto SDK m4 compatibility fix.

    Component bumps

    • audiodecoder → 0.2.0.0
    • audiomixer → 0.3.0.0 (breaking — DAP relocation + listener rename)
    • audiosink → 0.2.0.0
    • avbuffer → 0.2.0.0
    • avclock → 0.2.0.0
    • bootreason → 0.1.0.0 (renamed from boot)
    • common → 0.2.0.0
    • firmwareupdate → 0.2.0.0 (renamed from flash)
    • sensor → 0.2.0.0
    • videodecoder → 0.2.0.0
    • videosink → 0.2.0.0

    External component pinned:

    • linux_binder_idl → 2.3.0 (Yocto SDK m4 fix — see linux_binder_idl#30 and #31).

    Highlights

    Audiomixer

    • MS12 v2.6 DAP runtime control surface added: capability discovery, capture, profile selection. (#491)
    • getDolbyMs12_2_6_Dap() relocated from IAudioOutputPort to IAudioOutputPortController so DAP runtime control is gated by holding the exclusive port controller, matching the project's general read-handle vs write-controller pattern. (#594)
    • Listener API rename + boolean return: registerListener / unregisterListener → registerEventListener / unregisterEventListener on IAudioMixer and IAudioOutputPort; both now return boolean with the conventional duplicate-register / unknown-unregister semantics. State guards on getCurrentSourceCodecs() and getInputRouting() dropped (callable independent of open/close, like getCapabilities()). Full @exception / @retval / @see documentation added to the affected methods plus IAudioMixerController.setProperty and IAudioMixerManager.getAudioMixer. (#599, closes #597)

    Bootreason

    • Component renamed boot → bootreason to reflect actual scope (boot-reason classification only — not the full boot flow). The AIDL enum BootReason becomes Reason and methods are now getReason() / setReason(). (#576)

    Videodecoder

    • Colorimetry expanded to 4 independent axes so HDR metadata can describe each colour-primary / transfer / matrix / range dimension separately. (#549)

    Sensor

    • MotionEvent parcelable added carrying a monotonic timestamp for time-stable event correlation across other event sources. (#569)

    State machine / common

    • Per-module State.aidl migration — each module now ships its own State.aidl declaring only the states relevant to that module's lifecycle. common.State is deleted. (#556)
    • common.HALError.aidl deleted — no AIDL consumers were referencing it. (#555)

    Build + release infrastructure

    • release.sh completes: per-module stage workflow with worktree-driven plan, AIDL hash gate (suppresses bumps when the AIDL is byte-identical to the prior cohort), released-cohort verification build, persistent gh API cache, mkdocs mike deploy on --commit, snapshot creation + branch/tag automation. (#572, #578, #579)
    • Self-contained current/CMakeLists.txt for every module — modules build directly with cmake against their own current/ tree without depending on any aggregate top-level config. (#548)
    • Generated bindings (*/current/{include,src}/) are now treated as toolchain output, not source — gitignored on develop, regenerated on every build. The drift-check script catches stale committed copies. (#565, #567)

    Governance / docs

    • Explicit change-class labels required on every PR (Breaking Change / Major / Minor Change / Documentation). The version-bump workflow reads the labels to compute the next release version. (#547, #526)
    • AVBuffer lifecycle + vendor implementation boundary clarified in the docs. (#570)
    • HAL resource lifecycle page added to the architecture overview. (#499)

    Upgrade Guide

    Audiomixer call-sites

    If you implement or consume audiomixer:

    • Replace IAudioOutputPort::getDolbyMs12_2_6_Dap() with IAudioOutputPortController::getDolbyMs12_2_6_Dap(). Acquire the controller via IAudioOutputPort::open(listener) first.
    • Replace IAudioMixer::registerListener(listener) → bool IAudioMixer::registerEventListener(IAudioMixerEventListener audioMixerEventListener). Check the boolean return for "already registered". Same shape for unregisterEventListener.
    • Replace IAudioOutputPort::registerListener(listener) → bool IAudioOutputPort::registerEventListener(IAudioOutputPortListener audioOutputPortEventListener). Same shape for unregisterEventListener.

    Boot → Bootreason

    • Replace import com.rdk.hal.boot.* with import com.rdk.hal.bootreason.*.
    • Replace IBoot.aidl references with IBootReason.aidl. Method getBootReason() → getReason(); setBootReason(BootReason) → setReason(Reason); enum BootReason → Reason.

    Common.State removed

    • If you imported com.rdk.hal.common.State, switch to the per-module State.aidl in the module you're working with (e.g. com.rdk.hal.audiomixer.State).
    • Cross-module callers should branch on the originating module's State enum, not a shared one.

    Common.HALError removed

    • If you previously caught or constructed com.rdk.hal.common.HALError, switch to the standard binder exception types (EX_ILLEGAL_STATE, EX_ILLEGAL_ARGUMENT, etc.) per the per-method @exception documentation.

    Videodecoder Colorimetry

    • The single Colorimetry value is now a 4-element struct (colorPrimary, transferFunction, matrixCoefficient, range). Update any code that read or wrote a single value to consume / produce the four fields.

    Generated bindings no longer committed

    • If you build from a fresh checkout, run the host AIDL build first (./build_interfaces.sh sdk) before consuming the per-module C++ — generated */current/{include,src}/ directories are no longer in git and need to be produced by the toolchain.

    Yocto SDK builds

    • Bump your linux_binder_idl pin to 2.3.0 to pick up the m4 fix. If you previously hit m4: unrecognized option '--gnu' after sourcing the Kirkstone SDK env, this release resolves it. binder_sdk.version in the repo root is the pin.

    Removed

    • com.rdk.hal.common.HALError (no AIDL consumers).
    • com.rdk.hal.common.State (replaced by per-module State.aidl).
    • IAudioOutputPort::getDolbyMs12_2_6_Dap() (moved to IAudioOutputPortController).

    Coordination notes

    • Components still on 0.1.0.0 in this cohort (compositeinput, deepsleep, deviceinfo, drm, hdmicec, hdmiinput, hdmioutput, indicator, panel, planecontrol) are not pulled into the breaking-generation bump — no API change relative to 0.20.0.
    • The audiodecoder mid-stream sample-rate / channel-count spec (discussion #592) and the audiomixer AQ parameter API rework (PR #573) are deferred to 0.22.0.

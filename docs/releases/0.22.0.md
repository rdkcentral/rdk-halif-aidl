# RDK HALIF AIDL 0.22.0 Release Notes

Release date: 2026-07-22

Base comparison: `0.21.0...0.22.0`

## Headline

0.22.0 is the versioning-infrastructure release: every frozen snapshot now
bakes its real interface identity — `getInterfaceVersion()` returns the
release version as a positional int and `getInterfaceHash()` the toolchain
contract hash — and the release flow enforces a structural change-class
audit on every write path. Clients get one header, `halcompat.h`, that
answers compatibility and feature-gating questions identically before and
after a component adopts frozen-AIDL discipline. planecontrol takes its
first major bump, removing two provider methods that could never operate
across the binder boundary.

## Component bumps

- `planecontrol` → 0.2.0.0 (major)
- `avclock` → 0.2.0.1 (bugfix)
- `videodecoder` → 0.2.0.1 (bugfix)

`common` is **not** bumped: its AIDL interface (`AVSource`, `PropertyValue`,
the shared enums) is unchanged. The new `halcompat.h` is a client-side C++
helper, not part of any AIDL contract — it ships inside `common`'s existing
0.2.0.0 headers without moving the interface version. Interface version and
client-helper delivery are tracked separately.

## Highlights

### planecontrol 0.2.0.0 — removal of unusable functions

`IGraphicsFbProvider.getNativeDisplayHandle()` and `getEGLPlatformType()`
are removed (#621, from vendor feedback in discussion #620). A native
display is a process-local, vendor-specific object and cannot cross the
binder boundary; presentation is via `commitGraphicsFb()` (offscreen FBO
render), so EGL display/context setup is client-side. **Although this
carries the major bump — methods left the declared surface — the usable
interface is identical to 0.1.0.0: no working integration is affected.**
The vendor-neutral transformation guide
(`docs/transformation/westeros_graphics_fb_transform.md`) covers client-side
EGL setup. Also fixed: `onGraphicsFbReleased`'s second parameter is
`timestampNs` (absolute `CLOCK_MONOTONIC` swap time), fully documented for
commit-to-present latency measurement (#622).

### halcompat client compatibility helpers (ships in common 0.2.0.0)

New header-only `halcompat.h` (installed with the common headers) is the
single client-side home of version handling — clients never touch the
encoding or era rules (#710):

```cpp
auto svc = halcompat::getService<IBootReason>();
if (!halcompat::isCompatible(svc)) { /* absent, unfrozen, incompatible */ }
if (halcompat::atLeast(svc, 0, 2)) { /* gate on a released version */ }
```

The era rules (era 0: compatible within one major; era 1+: ordering
sufficient; dev builds rejected by default) are compile-time-proven by
static assertions inside the header.

### avclock 0.2.0.1 / videodecoder 0.2.0.1 (documentation)

Documentation-accurate contracts (bugfix tier — surface unchanged):
`IAVClock.open()` documents the real defaults and the sink-owned
`attachClock()` association model (#704, from discussion #703);
`getPropertyMulti` error semantics are exception-only with an explicit
no-return-value-on-exception rule (avclock, planecontrol, videodecoder).

### Release and versioning infrastructure

- **Real frozen identity everywhere**: all 21 released-cohort snapshots
  retrofitted to report their true `getInterfaceVersion()` (positional
  1-2-2-1 encoding, e.g. 0.2.0.0 → 2000) and `getInterfaceHash()`;
  newly frozen snapshots bake both automatically (#633).
- **Structural audit, default-on**: `release.sh --audit` classifies every
  component's last-frozen → `current/` AIDL diff (breaking / additive /
  doc-only via the binder toolchain's `dump-surface`/`diff-surface`) and
  cross-checks the PR-label class and declared metadata; it runs
  automatically on every stage/apply and refuses to write on disagreement
  (#568, #714).
- **Field-aligned change-class labels**: `Major Change` = breaking,
  `Minor Change` = additive, `documentation` = bugfix; a PR whose linked
  issue is GitHub type `Bug` implies the bugfix bump; the `Breaking
  Change` label is retired (#712).
- **Era/encoding contract published**: the AIDL Versioning Guide documents
  the four-field `<era>.<major>.<minor>.<bugfix>` scheme, the positional
  int encoding, the era promise, and the client compatibility model
  (#693); binder toolchain pinned at linux_binder_idl 2.6.0 (#698).

## Upgrade Guide

- **planecontrol integrations**: remove any references to
  `getNativeDisplayHandle()`/`getEGLPlatformType()` — they cannot have
  been functional cross-process. Perform EGL display/context setup
  client-side per the transformation guide, and render into the FBO
  committed via `commitGraphicsFb()`. Rename any use of the
  `onGraphicsFbReleased` second parameter to its documented
  `timestampNs` semantics.
- **All clients**: adopt `halcompat.h` for connection, compatibility and
  feature gating; direct `getInterfaceVersion()`/`getInterfaceHash()`
  calls belong only inside the helper. Note a frozen server now reports
  its real encoded version (e.g. 2000 for 0.2.0.0) instead of the
  generator default `1` — code comparing against small ordinals must move
  to `halcompat::atLeast()`.
- **Vendor implementations**: populate `onGraphicsFbReleased.timestampNs`
  with the real `CLOCK_MONOTONIC` swap time; report `"notfrozen"` hashes
  only from development builds.

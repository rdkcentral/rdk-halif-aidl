# RDK HALIF AIDL 0.23.1 Release Notes

Release date: 2026-11-27

Base comparison: `0.23.0...0.23.1`

## Headline

0.23.1 adds one parcelable that reports what an HDMI or audio output is
actually producing, on `hdmioutput` and `audiomixer` (#903), and defines the
decoders' behaviour on flush: who owns output buffers (#996) and what happens
to an end-of-stream that is still pending (#962). Every change is
backwards-compatible; no component takes a major bump.

## Component bumps

- `audiodecoder` → 0.3.1.0 (confirmed minor: Flush and EOS behaviour defined: output buffer ownership on flush (#890) and EOS still owed after a flush during EOS (#955); implementations must change.)
- `audiomixer` → 0.4.1.0
- `audiosink` → 0.3.0.1
- `hdmioutput` → 0.2.1.0
- `panel` → 0.2.0.1
- `videodecoder` → 0.3.1.0 (confirmed minor: Flush and EOS behaviour defined: output buffer ownership on flush (#890) and EOS still owed after a flush during EOS (#955); implementations must change.)

## Highlights

### Component interface changes

| Component | Change | PR |
| --- | --- | --- |
| `hdmioutput` | Adds `ActiveOutputFormat`, read with `IHDMIOutput.getActiveOutputFormat()` and delivered by `IHDMIOutputEventListener.onActiveOutputFormatChanged()`. Adds the `QuantizationRange` enum and `HDROutputMode.SDR`. | #903 |
| `audiomixer` | Adds `ActiveOutputFormat`, read with `IAudioOutputPort.getActiveOutputFormat()` and delivered by `IAudioOutputPortListener.onActiveOutputFormatChanged()`: format, channel layout and Atmos together. Reporting the resolved format through the `OUTPUT_FORMAT` property change is deprecated. | #903 |

### Behaviour changes (minor, confirmed)

- `audiodecoder` and `videodecoder`: output buffers already issued to the
  client stay owned by the client across `flush()`, and output in flight
  after an end-of-stream flush may still be delivered (#996). A `flush()`
  that lands while an EOS is pending still delivers the owed EOS once the
  flush ends; ordering across listeners is not promised (#962). HALs must
  implement both. The `FLUSHING` state's comment now names the states it
  returns to.

### Specification and documentation changes

- `hdmioutput`: HDCP status transitions when the HAL is stopped, and when an
  authenticated sink is unplugged (#999).
- `audiosink`: what `supportsPlanarFormat` accepts (#1025).
- `panel`: tone-mapping modes and levels (#1041).
- Test jig and test harness definitions (#1044).

## Upgrade Guide

1. **No rebuild is forced.** Every change is additive. HALs and clients built
   against 0.23.0 keep working.
2. **HDMI output and audio mixer HALs.** Implement `getActiveOutputFormat()`
   and fire `onActiveOutputFormatChanged()` whenever the produced format
   changes. Clients read the active format from there, not from the
   `OUTPUT_FORMAT` property change.
3. **Audio and video decoder HALs.** Keep output buffers already handed to
   the client valid across `flush()`, and deliver a pending EOS after a flush
   that interrupts it.

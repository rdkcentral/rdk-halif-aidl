# RDK HALIF AIDL 0.23.0 Release Notes

Release date: 2026-10-26

Base comparison: `0.22.0...0.23.0`

## Headline

0.23.0 moves every AIDL string to `std::string` in C++. #917 marks all
strings `@utf8InCpp`, so every component with a string in its interface, or
importing a type that has one such as `common`'s `PropertyValue`, takes a
major bump and must be rebuilt. The cohort also adds the Broadcast HAL with
DVB and ATSC 1.0 coverage, alongside a new `ringbuffer` component, and moves
the audio sink's `setProperty()` onto the controller. From this release the
release tooling takes each component's change class from the AIDL compiler
rather than from PR labels.

## Highlights

### Strings are `std::string` in C++ (#917)

Every `String`, `String[]` and `@nullable String` in the AIDL is now
`@utf8InCpp`, so the generated C++ uses `std::string` (and `std::vector` /
`std::optional` of it) instead of `android::String16`. The wire format is
unchanged, because binder carries UTF-16 either way, but the C++ source
contract has changed. #917 also adds AIDL validation tooling to the build.

### Broadcast HAL and ringbuffer (#258)

`broadcast` 0.1.0.0 extends the Broadcast HAL to cover DVB-T/C/S and
ATSC 1.0. `ringbuffer` 0.1.0.0 is new and carries the shared ring buffer
it uses.

### Specification changes

- `sensor` (thermal): there is now one state machine per sensor, with start-up
  and cooldown expiry defined, and `getCurrentThermalState()` returns the
  worst state across sensors. `CRITICAL_TEMPERATURE_RECOVERED` is deprecated
  (#846).
- `audiodecoder`: mid-stream in-codec format changes (#600); codec priming,
  padding and gapless trim (#489); Opus output is always 48 kHz.
- `audiomixer`: output ports are written in READY, and DAP support is read
  from `supportedAQProcessors` (#884).
- `hdmiinput`: VRR, session release on client death and initial-state events
  (#800). `audiosink` and `videosink`: behaviour with no output attached
  (#795) and the decoder association contract (#762).
- Generated headers now carry the AIDL doc comments as Doxygen (#909).

### Release tooling

`release.sh` now classifies each component with the AIDL compiler. It runs
`--checkapi` for the wire contract, then compares regenerated C++ headers,
including changes inherited through imported types. PR labels and the
Interface Effect field are hints, and any disagreement is listed with links.
To override the compiler, run `stage --confirm <class> "<reason>"`; the
reason is recorded in the release notes (#875, #920, #923, #926).

## Upgrade Guide

1. **Rebuild everything against 0.23.0.** Every major-bumped component
   changes its generated C++. A HAL or client built against 0.22.0 headers
   does not compile against 0.23.0 headers.
2. **Strings.** Replace `android::String16` with `std::string` in every
   HAL override and client call, and drop `String8`/`String16` conversions.
   Values are UTF-8.
3. **Audio sink.** Call `setProperty()` on the `IAudioSinkController` returned
   by `open()`, not on `IAudioSink`. Use `setAtmosLock()` on the DAP interface
   instead of `DOLBY_ATMOS_LOCK`. Read the sample-rate and PCM-format arrays
   from `PlatformCapabilities`.
4. **Decoders.** Stop setting `InputBufferMetadata.discontinuity` and call
   `signalDiscontinuity()`. Video decoder HALs remove the operational-mode
   API, and audio decoder HALs implement `getCurrentOperationalMode()`.
5. **Panel.** Rebuild PQ capability tables against the new
   `PQParameterCapabilities`, and never persist `PQParameter` ordinals across
   the upgrade, because the values have changed.
6. **HDMI-CEC.** Check that `addLogicalAddresses()` rejects the address sets
   listed in the table above.
